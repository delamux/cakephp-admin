# Deploying on Coolify

`compose.coolify.yaml` (**Docker Compose** build pack): Coolify builds the images from the repository on every deploy
and its proxy (Traefik + Let's Encrypt) puts HTTPS in front of nginx. No port is published.

```
Internet ──HTTPS──> Traefik (Coolify) ──HTTP──> web (nginx) ──FastCGI──> app (PHP-FPM) ──> PostgreSQL (Coolify resource)
                                                                        worker (queue) ──┘     └── real SMTP
migrate (once per deploy: bin/deploy = migrations + permissions sync)
```

| Service | Image (Dockerfile target) | What it does |
| --- | --- | --- |
| `web` | `web` | nginx with the static files; `/healthz` for the health check |
| `app` | `prod` | PHP-FPM |
| `worker` | `prod` | `bin/cake queue run` (emails and jobs) |
| `migrate` | `prod` | `bin/deploy` and exits (`restart: "no"`, excluded from the health check); `app` and `worker` wait for it to finish successfully |

## Step by step

1. **Repository** on GitHub (or GitLab/Gitea) accessible to Coolify.
2. **Database:** *New Resource → Database → PostgreSQL 18* on the same server. Enable **scheduled backups** (S3) and
   copy its **Internal URL** (`postgres://user:password@<container>:5432/<db>`).
3. **Application:** *New Resource → Application* from the repository, **Docker Compose** build pack, file
   `/compose.coolify.yaml`.
4. **Network:** *Advanced → Docker compose → Connect to predefined network*, so the containers can reach the
   database.
5. **Domain:** on the `web` service, the final domain (`https://admin.example.com`). Coolify puts it in
   `SERVICE_URL_WEB` → `APP_FULL_BASE_URL`. **Choose it before anyone registers keys or passkeys**: they are bound to
   it.
6. **Variables** (*Environment Variables*):
   - `DATABASE_URL`: the Internal URL from step 2.
   - `EMAIL_TRANSPORT_DEFAULT_URL`: the real SMTP (`smtp://user:password@smtp.example.com:587?tls=true`).
   - `EMAIL_FROM` (and optionally `EMAIL_FROM_NAME`).
   - `SECURITY_SALT` and `COOKIE_KEY` are generated by Coolify the first time (`SERVICE_HEX_64_*`) and kept:
     **don't change them** (it would end every session and invalidate the "remember me" cookies).
   - Optional: `TWO_FACTOR_ENABLED`, `SESSION_TIMEOUT`, `TRUSTED_PROXIES` (default: Docker's private ranges; see
     [Security](security.md#trusted-proxies)).
7. **Deploy.** `migrate` creates or updates the schema and registers the actions; then `app`, `worker` and `web`
   start.
8. **First superadmin** (first time only), from the *Terminal* of the `app` container:
   ```bash
   bin/cake users add_superuser -u admin -e admin@example.com    # without -p it generates and shows the password
   ```
9. **Daily task:** *Scheduled Tasks → Add*: name `maintenance`, command `bin/cake maintenance`, frequency
   `0 3 * * *`, container `app`. It's the only cron ([Operations](operations.md)).
10. **Check:** sign in as the superadmin, look at *System › Queue* (there should be a live worker) and request a
    password reset to see that the email arrives.

## Every deploy

Push → Coolify builds → `migrate` (migrations + new actions in the permissions catalogue) → `app`, `worker` and `web`
are replaced. Sessions and the queue live in PostgreSQL: nobody loses their session and no jobs are lost (the worker
finishes its current job before stopping). If `migrate` fails, `app` and `worker` don't start with the new code and
the deploy is marked as failed: check the `migrate` log in Coolify.

## Notes

- **Uploaded files** (user photos): `uploads` volume, which Coolify keeps across deploys. Include it in your backups
  ([File uploads](uploads.md#storage)).
- Scaling: `worker` replicas are fine (state lives in PostgreSQL); for `app`, **only one** while files are on the
  local volume (for more, S3 storage).
- Logs: everything goes to stderr (*Logs* of each service in Coolify). What to watch: [Operations](operations.md#logs).
- There's no Mailpit in production: you need a real SMTP (Postmark, SES, Mailgun, your domain's…).
- To try something similar locally: `compose.prod.yaml` (same images, automatic migrations and worker).
